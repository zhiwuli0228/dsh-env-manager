# Design Rule

A design document explains how a feature will be built.

## Required Sections

### 1. Overview

What is being designed and why.

### 2. Data Flow

Step-by-step flow with input/output boundaries.

### 3. Module Allocation

Which modules are involved and what each owns.

### 4. Schema Changes

New or changed YAML/JSON schemas.

### 5. Security Considerations

Credential handling, approval policies, production access.

### 6. Error Handling

Expected failure modes and responses.

### 7. Verification Plan

Tests and manual checks.
