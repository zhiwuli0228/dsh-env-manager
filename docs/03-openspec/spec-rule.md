# Spec Rule

A spec document turns a proposal into actionable implementation details.

## Required Sections

### 1. Objectives

Clear, measurable outcomes.

### 2. Functional Requirements

What the system must do.

### 3. Non-functional Requirements

Performance, security, compatibility constraints.

### 4. Interface Definitions

Tool names, parameters, return values, events.

### 5. Data Definitions

Schemas for inputs, outputs and storage records.

### 6. Acceptance Criteria

Specific conditions that must be met.

### 7. Open Questions

Unresolved items to confirm before implementation.
