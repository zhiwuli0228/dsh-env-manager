# Change Snapshot Policy

## Purpose

Preserve project continuity by documenting what changed and why after each meaningful change.

## When to Update

Update `docs/00-project/current-state.md` when:

- a new feature is implemented
- a bug is fixed
- a storage contract changes
- a module boundary changes
- a known gap is closed

## What to Record

- What changed (high-level)
- Which files were added/removed/modified
- Any new constraints or dependencies
- Remaining known gaps
- Recommended next work

## What Not to Record

- Every single commit detail (git history covers that)
- Temporary workarounds without context
- Opinion or speculation
